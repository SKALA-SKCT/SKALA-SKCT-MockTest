# 응시 중 배포

응시 화면은 `/api/exam/{examId}/session`으로 요청합니다. 배포마다 달라지는 Server Action 식별자에 의존하지 않습니다. 이후 배포에서도 이 API의 주소, 요청 필드, 응답 형식을 유지해야 합니다.

화면을 다시 열면 미완료 응시 번호, 서버에 기록된 유형 시작 시각과 답안을 복원합니다. 화면 이탈 알림으로 응시를 삭제하던 API는 410을 반환합니다. 사용자가 나가기를 확인한 경우에만 해당 응시를 삭제합니다.

저장 대기 답안은 응시 번호별로 `sessionStorage`에 보관합니다. 저장은 순차 처리하며 실패하면 3초마다 재시도합니다. 서버의 저장 확인을 받은 뒤 제출합니다. 새로고침 이후에도 저장 대기 답안을 복원합니다. 제한시간은 서버 기준으로 유지하며 기존 저장 유예는 30초입니다. 이 시간을 넘긴 통신 장애에서는 저장 대기 답안이 서버에서 거절될 수 있습니다. 브라우저 보관 데이터를 임의로 삭제하지 않습니다.

현재 Vercel 팀의 요금제는 Hobby입니다. 서버 버전을 고정하는 Skew Protection은 Pro 또는 Enterprise에서 사용할 수 있습니다. 유료 기능은 활성화하지 않았습니다. 설정 근거는 [Vercel 공식 문서](https://vercel.com/docs/skew-protection)입니다.

Pro 전환 후 버전 고정을 도입할 때는 Skew Protection, 배포 보존 기간과 최대 배포 나이를 함께 확인해야 합니다. 최대 나이는 배포 생성 시각부터 계산합니다. 응시 시작 시 `__vdpl` 쿠키를 설정하고 완료 또는 명시적 중단 시 지우는 방식으로 전체 페이지 요청도 고정할 수 있습니다.

DB 변경은 기존 배포가 사용하는 컬럼과 형식을 유지하면서 적용합니다. 컬럼 삭제나 응답 형식 변경은 기존 응시가 끝난 뒤 진행합니다. 이번 수정에는 DB 스키마 변경이 없습니다.

## 검증

`node --import tsx --test tests/statistics.test.ts tests/exam-recovery.test.ts`로 중앙값, 보관 데이터 검증, 저장 실패 보존, 저장 중 선택 변경을 확인합니다.

통합 검증은 분리된 로컬 PostgreSQL과 앱에서 실행합니다. `EXAM_TEST_DATABASE_URL`, `EXAM_TEST_APP_URL`, `EXAM_TEST_SESSION_SECRET`을 지정하고 `node --import tsx tests/exam-session.integration.ts`를 실행합니다. 앱과 DB 주소는 `127.0.0.1`이어야 합니다. 검증용 사용자와 시험만 생성하며 실행 후 정리합니다. `EXAM_TEST_NEXT_APP_URL`을 추가하면 저장 후 다른 로컬 서버로 전환해 같은 응시를 복원하고 제출합니다.

기존 화면을 열어 둔 사용자는 이번 첫 배포의 새 클라이언트 코드를 즉시 받지 않습니다. 다음 접속부터 API와 답안 보관 변경이 적용됩니다. 실제 배포 중인 기존 응시 화면의 연속 동작까지 확인한 결과는 별도로 기록해야 합니다.
